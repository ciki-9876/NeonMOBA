# NEON DRIFT · 角色设计规范（固定世界）

> 状态：第一版（2026-11-26），待确认。
> 背景：世界改为「固定世界 + 蝴蝶效应」（见 `游戏框架与开发路线.md`）。选手、教练、老板等角色是固定的、有完整设定的人物，前世记忆、转会和剧情都建在他们身上。
> 本文规定「一个角色的设计要包含哪些要素」，作用类似 `新英雄制作规范`。初稿见 `角色设定初稿_第一赛季.md`。

## 一、角色分层

| 层 | 规模 | 要求 | 每局是否固定 |
|---|---|---|---|
| **核心角色** | 全游戏约 40–50 人，第一赛季先做约 15–18 人 | 本文**全部要素** | 固定（实际成长每局有随机） |
| **常规角色** | 约 30–50 人 | 第二节的「必填」要素 + 一句话背景 + 性格；不写专属剧情和前世轨迹细节 | 固定 |
| **路人** | 每局生成 | 由模板生成名字、能力、一句话背景、性格 | 每局随机 |

核心角色包括：主角、前世队友、宿敌、各队明星、未来巨星新人、关键教练和老板、少量媒体人。

**战队编制**：每队 4 人（3 名首发 + 1 名替补）。替补让转会、轮换、「坐板凳」这类剧情有空间。现在的代码每队只有 3 人，做世界延续时一起改。

## 二、角色要素

每个要素都写明它驱动哪个系统。驱动不了任何系统的设定，只写进背景文字，不单列字段。

### 1. 身份（必填）

| 字段 | 说明 |
|---|---|
| `id` | 英文小写，全局唯一，如 `bear` |
| 真名 | 中文姓名 |
| 选手 ID | 比赛里显示的名字，如「大熊」「Zero」。中文昵称和英文 ID 都可以，全游戏不重名 |
| 初始年龄 | 第一赛季开始时的年龄（不写具体年份） |
| 身份 | 选手 / 教练 / 老板 / 媒体 / 其他 |
| 职业位置 | 坦克 / 输出 / 辅助（选手才有） |
| 初始所属 | 第一赛季开始时在哪支队、首发还是替补；或者自由身、青训、路人赛 |
| 一句话定位 | 15 字以内，让玩家一眼记住，如「网吧里最能扛的胖子」 |

### 2. 外观（核心角色必填）

| 字段 | 说明 |
|---|---|
| 外观关键词 | 3 个，如「寸头、黑框眼镜、旧队服」，给美术用 |
| 代表色 | 一个颜色，用于聊天头像框、新闻配色 |
| 表情 | 至少 4 个：平常、开心、生气、低落；核心剧情角色可加专属表情 |
| 半身像 | 像素风，建议 64×64（剧情插图里的出场另画） |

### 3. 能力（必填，选手）

| 字段 | 驱动的系统 | 说明 |
|---|---|---|
| 6 项能力初始值 | 对战 AI（`profiles.gd`）、直接出结果 | 反应、操作、意识、决断、配合、心态，1–20 |
| **潜力区间** | 训练成长上限 | 能力平均值的上限，写成区间，如「15–18」。每局开局在区间内抽一个实际上限，所以同一个人每局长成的高度不一样 |
| 成长侧重 | 训练和自然成长 | 哪 2 项能力长得快，如「操作、反应」 |
| **成长曲线** | 能力随年龄的变化 | 早熟（巅峰 18–20 岁）/ 标准（21–23）/ 晚成（23–25）/ 昙花（巅峰早而短，之后下滑快）。巅峰后约 3 年开始下滑 |
| 英雄池 | 禁选、熟练度 | 本职业 4 个英雄的熟练度（0–100），可再加 1–2 个其他职业的英雄 |
| 擅长英雄 | 熟练度成长 ×2、专属能力 | 1–3 个，每个可指定专属能力（`runes_db.gd` 的 SIGNATURES），没有合适的就留空，等内容补上 |
| 特质 | 比赛中的情境修正 | 0–2 个，从特质表里选（残局之王、大赛型、慢热、开团手、英雄池狭窄，可以扩充） |

**数值约束**（对应联赛档次，见 `赛事层设计.md`）：
- 第一赛季开局：豪门首发平均约 13，中游约 11，新军约 9.5；单项能力最高 17，最强的明星平均不超过 16。
- 「未来巨星」开局平均 8–11，潜力上限 ≥ 17。
- 潜力区间宽度 2–4。区间越宽，这个人越「看命」。

### 4. 性格（必填，选手和教练）

五项，0–10，玩家默认看不到具体数值，只能从聊天、新闻和事件里感觉出来（球探或高级情报可以显示）：

| 性格 | 驱动的系统 |
|---|---|
| **野心** | 想去能夺冠的队、想当首发；野心高的人在弱队待不住，坐板凳会很快要求转会 |
| **忠诚** | 抵抗挖角；被卖时心态打击大；忠诚高的人难挖，但一旦挖到也难被别人挖走 |
| **物欲** | 谈判时对薪水和签字费的看重程度 |
| **自尊** | 被替换、被批评、输给宿敌时的反应；自尊高的人宿敌剧情更激烈，也更容易「打脸」逆袭 |
| **合群** | 和队友的化学反应；合群低的人和别人起冲突，合群高的人对朋友有配合加成 |

和能力里的「心态」区分：心态管比赛中的压力表现，性格管比赛外的选择和关系。

### 5. 说话风格（核心角色必填）

用于手机私信、论坛、采访。写清楚，之后按它批量写台词。

| 字段 | 例子 |
|---|---|
| 语气 | 话少、客气、嘴臭、中二、东北腔…… |
| 口头禅 | 1–2 句 |
| 示例台词 | 至少 3 句：平时私信、赢了之后、被挖角或谈判时 |

### 6. 背景（必填，核心角色写详细）

| 字段 | 说明 |
|---|---|
| 前史 | 150 字以内：出身、怎么开始打比赛、和谁有过节 |
| **前世结局** | 原本的历史里，这个人最后怎么样了（主角记得的版本） |
| 今生可能 | 玩家介入后，他可能走向哪几种不同的结局 |

### 7. 人物关系（核心角色必填）

列表，每条：对象、关系类型、强度（1–3）、来历。

关系类型：兄弟（主角的前世队友）、朋友、宿敌、师徒、前队友、上下级。

驱动的系统：同队的朋友有配合加成、宿敌之间对决时双方心态波动、师徒带新人成长加快、宿敌事件和新闻。

### 8. 原本轨迹（核心角色必填）

「前世」里这个人每个赛季发生的关键事件。世界在玩家不插手时按它推进；玩家改变了前提条件，这条就不再发生（蝴蝶效应）。

每条：赛季（S1–S6）、时间点（赛季前 / 第几周 / 季后赛 / 休赛期）、事件类型、内容、**前提条件**。

事件类型：能力突破、转会、合同纠纷、和队友或老板闹翻、伤病、退役、夺冠、获奖、丑闻、转型（选手转教练等）。

前提条件例子：「仍在原队」「原队这赛季没进季后赛」「没有和玩家的战队签约」。

### 9. 前世笔记条目（核心角色必填）

从原本轨迹里挑出主角**记得**的事件，写成笔记条目：

| 字段 | 说明 |
|---|---|
| 条目文字 | 主角视角的一句话，如「天穹的 Zero，S1 拿下世界冠军，决赛 MVP」 |
| 清晰度 | 清楚 / 模糊（模糊的只给大概，如「S2 中期好像和老板闹翻了」） |
| 想起的时机 | 开局就记得 / 见到本人后想起 / 某个事件触发 / 需要局外成长解锁 |

主角不会记得所有事：他前世只是个不得志的选手，只记得他关注过的人和大新闻。

### 10. 专属剧情（核心角色 1–3 个）

每个事件：触发条件、呈现方式（手机私信 / 剧情插图 / 论坛热帖）、玩家选项（2–3 个）、每个选项的后果（关系、性格、能力、去留的变化）。

### 11. 合同与名气（选手必填）

| 字段 | 说明 |
|---|---|
| 名气 | 0–100。影响身价、赞助、媒体关注 |
| 初始合同 | 剩余年限、周薪档位（低 / 中 / 高 / 顶薪） |
| 特殊条款 | 可选：违约金、不可交易、到期自动续约等 |

身价不手写，由能力、潜力、年龄、名气、合同算出来。

## 三、数据格式

角色数据放在 `game/league/cast_db.gd`（和 `heroes_db.gd` 同样的写法，纯数据）。示例：

```

	"name": "熊磊", "handle": "大熊", "age": 21, "kind": "player", "role": "tank",
	"team": "spark", "slot": "starter", "tagline": "网吧里最能扛的胖子",
	"look": ["寸头", "大块头", "洗白的旧队服"], "col": Color(0.85, 0.6, 0.3),
	"attrs": {"reaction": 8, "mechanics": 9, "awareness": 10, "decision": 9, "teamwork": 13, "composure": 11},

	"prof": {"anchor": 82, "aegis": 55, "frost": 40, "rail": 25},
	"sig": {"anchor": "anchor_wide_hook"}, "traits": [],
	"persona": {"ambition": 3, "loyalty": 9, "greed": 6, "pride": 4, "social": 8},
	"voice": {"tone": "憨厚、话不多", "catch": ["没事，我扛着。"], "lines": ["...", "...", "..."]},
	"fame": 5, "contract": {"years": 1, "pay": "low"},
	"bio": "...", "past_end": "...", "futures": ["...", "..."],
	"links": [{"who": "hero_pc", "type": "brother", "lv": 3, "why": "..."}],
```

## 四、制作流程

1. **定位**：这个角色在故事里起什么作用（兄弟、宿敌、捡漏目标、挖角目标、警示、导师），在哪个赛季登场。
2. **先写原本轨迹和前世结局**，再倒推能力、潜力、性格。故事决定数值，不要反过来。
3. **对照数值约束**检查能力和潜力。
4. **写关系**：每个核心角色至少和 2 个其他角色有关系，其中至少 1 个关系是冲突（宿敌、不和、竞争）。
5. **挑笔记条目**：只挑主角会关心的事，并想好玩家怎么利用这条信息。
6. **写说话风格和示例台词**。
7. **专属剧情**：至少 1 个有真实取舍的选择，不能有「明显正确」的选项。
8. **美术**：外观关键词交给美术，生成半身像和表情。

## 五、自查清单

- [ ] 一句话定位能让人记住，和其他角色不重复
- [ ] 能力、潜力符合档次约束
- [ ] 原本轨迹的每个事件都有前提条件，玩家有办法改变它
- [ ] 至少 1 条笔记条目能被玩家利用（捡漏、挖角、避坑、备战）
- [ ] 性格和原本轨迹一致（例如忠诚 9 的人不会在原本轨迹里主动跳槽，除非有强烈原因并写明）
- [ ] 至少 2 条关系，其中 1 条是冲突
- [ ] 专属剧情的选项都有代价
- [ ] 说话风格有 3 句以上示例台词
- [ ] 名字、选手 ID 不和已有角色、英雄名重复
