# NEON DRIFT · 角色设计与制作规范（协作者版）

> 状态：第二版（2026-11-26）。
> 用途：多名协作者（人或 Agent）批量设计、制作角色时遵守的规范，作用类似 `新英雄制作规范`。
> 属性的含义和机制见 `角色机制设计.md`；世界和已有角色见 `角色设定初稿_第一赛季.md`。
> 目标：**新增一个角色 = 一张设定卡 + 一个数据条目 + 若干事件条目 + 半身像，不改系统代码。**

## 一、协作方式

### 1. 分工

| 角色 | 负责 | 产出 |
|---|---|---|
| 世界总编（1 人） | 角色总表、世界年表、关系总表；分配空位；审核 | 三张总表、审核意见 |
| 角色作者（多人） | 按需求单设计角色 | 设定卡、数据条目、专属事件 |
| 美术 | 按外观关键词出半身像和表情 | 图片资源 |
| 开发（可与作者是同一人） | 录入数据、跑校验 | `cast_db.gd`、`events_db.gd` 的条目 |

### 2. 三张总表（只有世界总编能改）

| 总表 | 内容 | 位置 |
|---|---|---|
| **角色总表** | 每个角色一行：id、真名、选手 ID、性别、国籍、位置、S1 所属和首发 / 替补、层级（核心 / 常规）、故事功能、作者、状态（待写 / 已写 / 已审 / 已录入） | `docs/design/角色总表.md`（待建） |
| **世界年表** | 按赛季、时间点列出所有原本轨迹事件，包括世界事件 | 同上，或角色设定稿的「前世大事年表」 |
| **关系总表** | 所有关系，每条两个人、类型、强度 | 同上 |

**冲突规则**：作者写的原本轨迹和关系，要先提交给世界总编合进总表；同一个时间点同一个首发位置只能有一个人，两个人的轨迹不能互相矛盾（例如两人在同一休赛期都转去天穹当首发输出）。

### 3. 流程

1. **需求单**：世界总编从角色总表分配一个空位，写明：战队和位置（或自由身）、层级、性别、国籍、档次、故事功能、登场赛季、必须有的关系（例如「Zero 的跟班」）。
2. **设计**：作者按第三节填写设定卡（Markdown）。
3. **审核**：世界总编按第七节检查；通过后把原本轨迹和关系合进总表。
4. **录入**：开发按第四节把设定卡写成数据条目和事件条目。
5. **美术**：按外观关键词出图。
6. **校验**：跑第六节的自动检查和回放测试。
7. **提交**：一个角色一次提交；说明写角色名、层级、故事功能、已校验项。

## 二、配额与预算（批量设计时的硬约束）

| 约束 | 规则 |
|---|---|
| 战队编制 | 每队 4 人：3 名首发 + 1 名替补 |
| 性别 | 所有有名字的选手中，女性约 1/3（按全体统计，不要求每支队都有） |
| 国籍 | 俱乐部不绑定国籍。所有选手中本地（中国）约一半，其余分散到多个国家；同一支队的首发里，如果三人没有共同语言，要在设定里写明原因（这会带来沟通惩罚） |
| 能力 | 第一赛季开局，豪门首发平均约 13，中游约 11，新军约 9.5；单项最高 17；最强明星平均不超过 16 |
| 潜力 | 区间宽度 2–4；「未来巨星」开局平均 8–11，上限 ≥ 17；每个赛季可以出现的「未来巨星」不超过 3 个 |
| 年龄 | 选手 16–30 岁；每支队至少 1 名 20 岁以下的选手 |
| 名气 | 豪门明星 60–85，普通首发 10–40，新人 0–10 |
| 专属事件 | 核心角色 1–3 个；常规角色 0 个 |
| 英雄 | 擅长英雄必须是 `heroes_db.gd` 的 `ORDER` 里的英雄；专属能力必须是 `runes_db.gd` 的 SIGNATURES 里的 id，没有合适的就留空 |

## 三、设定卡模板

核心角色填全部；常规角色只填标 ★ 的项。

```markdown
### 角色名 · 真名「选手 ID」

| 项 | 内容 |
|---|---|
| ★ 身份 | 选手 / 教练 / 老板 / 媒体 · 位置 · 初始所属（首发 / 替补 / 自由身）· 初始年龄 · 性别 · 国籍 |
| ★ 语言 | 例：中文 3、英语 1 |
| ★ 一句话 | 15 字以内 |
| 外观 | 3 个关键词；代表色 |
| ★ 能力 | 反应 / 操作 / 意识 / 决断 / 配合 / 心态 |
| ★ 潜力 | 区间；成长曲线；侧重的 2 项能力 |
| ★ 英雄 | 擅长英雄（专属能力）；其余英雄的熟练度 |
| ★ 性格 | 野心 / 忠诚 / 物欲 / 自尊 / 合群 |
| ★ 名气 / 合同 | 名气；年限、薪资档位、特殊条款 |
| 特质 | 0–2 个 |

**说话风格**：语气、口头禅；示例台词 3 句（平时私信 / 赢了 / 被挖角或谈判）
**★ 背景**：前史（150 字以内）
**前世结局**：原本历史里最后怎样
**今生可能**：2–4 个结局，每个写达成条件
**关系**：对象、类型、强度 1–3、来历（至少 2 条，其中 1 条是冲突）
**原本轨迹**：每条：赛季、时间点、事件、前提条件、概率
**前世笔记**：每条：文字、清晰度、想起的时机、绑定哪条轨迹
**专属事件**：每个：触发条件、呈现方式、选项（2–3 个）和后果
**玩法意义**：玩家为什么会关心这个人（捡漏、挖角、宿敌、导师、警示……）
```

## 四、数据格式（2026-11-26 按 M1 / M2 的实现更新）

角色的数值和身份放在 `game/league/cast_db.gd`；原本轨迹、事件、前世笔记、结局放在 `game/story/events_db.gd`（每条带 `owner` 指向角色）。设定卡里的文字（说话风格、背景、前世结局）目前只在设定稿里，进剧情和界面时再录入。

### 1. 角色条目（`cast_db.gd`）

**核心角色**（`CORE`）：

```
"bear": {"name": "熊磊", "handle": "大熊", "role": "tank", "team": "spark", "slot": "starter", "gender": "m", "nation": "CN",
	"langs": {"zh": 3}, "age": 21, "attrs": [8, 9, 10, 9, 13, 11], "potential": [13, 15], "curve": "late",
	"focus": ["awareness", "teamwork"], "prof": {"anchor": 82, "aegis": 55, "frost": 40, "rail": 25}, "sig": {"anchor": "anchor_wide_hook"},
	"persona": [3, 9, 6, 4, 8], "fame": 2, "contract": [1, "low"], "tagline": "网吧里最能扛的胖子"},
```

- `attrs` 顺序：反应、操作、意识、决断、配合、心态。`persona` 顺序：野心、忠诚、物欲、自尊、合群。
- `slot`：`starter` / `bench` / `free`（自由身）。`curve`：`early` / `standard` / `late` / `flash`。`contract`：[剩余年限, `low`/`mid`/`high`/`top`]。
- `gender`：`m` / `f`；`nation`：两位国家代码；`langs`：语言代码 → 0–3。

**常规角色**（`REGULAR`）只写身份，数值由 `world.gd` 用固定种子 `CAST_SEED` 围绕战队均值生成，每局都一样：

```
"polar": {"handle": "Polar", "role": "support", "team": "aur", "slot": "starter", "gender": "f", "nation": "SE", "age": 21,
	"langs": {"sv": 3, "en": 3, "zh": 1}, "boost": 1.5},     # boost：比战队均值高多少
```

**次级联赛各队**的选手目前全部由固定种子生成（名字、能力、性别、国籍），之后由作者逐步替换成常规或核心角色。

**职员**（`STAFF`）：教练、老板、媒体，`kind` 为 `coach` / `owner` / `media`；教练暂时只有一个技能占位（`skill`，见 `COACH_SKILLS`）。

**关系**（`LINKS`）：`[甲, 乙, 类型, 强度 1–3]`，类型和初始值见 `LINK_VALUE`（兄弟 +30、朋友 +25、师徒 +20、崇拜 +15、上下级 +15、宿敌 −25，再乘以 0.5 + 0.5 × 强度）。

**战队**（`TEAMS`）：名字、简称、联赛（`pro` / `sec`）、档次、生成常规选手用的能力均值、颜色。

### 2. 原本轨迹（`events_db.gd` 的 `TIMELINE`）

```
{"id": "rex_to_sky", "owner": "rex", "s": 2, "at": "off", "if": [["team_of", "rex", "rf"], ["flag", "rex_unhappy"]], "p": 0.9,
	"do": [["move", "rex", "sky"]], "news": "{rex} 加盟天穹，天穹为他配了专职翻译。"},
{"id": "fish_offer", "owner": "fish", "s": 1, "at": "off", "if": [["team_of", "fish", "spark"]], "p": 1.0, "event": "fish_sky_offer",
	"result": [["team_of", "fish", "sky"]]},
{"id": "sky_s1_title", "owner": "world", "s": 1, "at": "end", "check": true, "if": [["champion", "pro", "sky"]]},
```

- `at`：`pre`（赛季开始）、`w<N>`（第 N 周开始）、`po`（季后赛开始）、`end`（赛季结束，休赛期之前）、`off`（休赛期）。
- `do`：直接发生的效果；`event`：一个选择事件，牵涉玩家战队时让玩家选，否则自动按 `past`（原本的选择）处理；`result`：选择之后用来判断原本的结果是否出现。
- `check: true`：只观察，不改变世界（例如「S1 冠军是天穹」）。
- 文字里的 `{id}` 会替换成角色或战队的名字。

### 3. 事件条目（`events_db.gd` 的 `EVENTS`）

```
"bear_family_call": {"kind": "major", "show": "phone_chat", "who": "bear",
	"text": "{bear}：阿驰……我妈又打电话了……",
	"choices": [
		{"label": "给他加薪", "effects": [["contract_pay", "bear", "mid"], ["persona", "bear", "loyalty", 1], ["flag", "bear_stayed"]]},
		{"label": "尊重他的决定，赛季结束后放他走", "past": true, "effects": [["flag", "bear_leaving"]]},
	]},
```

- 每个选择事件**必须正好有一个** `past: true` 的选项（原本历史里的选择，AI 和回放测试用它）。
- `auto: true` + `branches`：不需要玩家选，按条件自动走分支（例如「让小鱼自己决定」）。
- **通用事件**（`GENERIC`）：`{"id", "who": "player" | "pair", "if", "p": 每周概率, "cool": 冷却周数, "ai": AI 战队的效果}`，`id` 同时是给玩家看的选择事件；条件和效果里用 `$p`、`$q`（当事人）、`$t`（战队）。
- **前世笔记**（`NOTES`）：`{"id", "bind": 绑定的轨迹, "when": "start" | "season:N" | "week:N" | "meet:<角色>", "clear", "text"}`。
- **结局**（`ENDINGS`）：每个角色一列 `{"text", "if"}`，按顺序取第一个满足的。

### 4. 条件和效果的词汇表

所有角色共用一套词汇，**不要为单个角色发明新词**。缺少的词提交给世界总编，由开发统一加到 `game/story/rules.gd`。比较符：`>=`、`<=`、`>`、`<`、`==`、`!=`。

**条件**：

| 类别 | 条件 |
|---|---|
| 时间 | `season`、`week`、`phase` |
| 所属 | `team_of`（`""` = 自由身）、`same_team`、`free_agent`、`human_team`、`league_of`、`role`、`retired`、`suspended`、`staff_free`、`coach_of` |
| 战绩 | `team_rank`、`streak`、`made_playoffs`、`champion`（联赛、战队） |
| 角色状态 | `attr_avg`、`fame`、`fatigue`、`form`、`satisfaction`、`bench_streak`、`age`、`persona`、`contract_pay`、`comm_low`（和队友的平均共同语言低于某级） |
| 关系 | `rel` |
| 剧情 | `flag`、`happened`、`failed`、`not`、`any` |

**效果**：`attr`（某项或 `all`）、`prof`、`potential`、`persona`（每次最多 ±1）、`trait_add` / `trait_remove`、`fame`、`form`、`satisfaction`、`respect`、`fatigue`、`lang`、`rel`、`contract_pay`、`move`（转会，满员时自动放走最不影响阵容的人）、`release`（解约成为自由身）、`retire`、`coach`（职员加入某队）、`flag` / `unflag`、`news`、`chain`（接续另一个事件）、`recall`（得到一条前世笔记）、`money`、`suspend` / `suspend_team`（停赛周数）、`relegate`（逐出职业联赛）、`fold`（战队解散重组）。

### 4. 命名

- 角色 id：英文小写，用选手 ID 或拼音，全局唯一，例如 `bear`、`zero`。
- 事件 id：`<角色id>_<主题>`，例如 `bear_family_call`；通用事件用 `gen_<主题>`；世界事件用 `world_<主题>`。
- 选手 ID 不能和英雄名、其他选手重复。

## 五、写作规则

1. **先写原本轨迹和前世结局，再倒推数值。** 故事决定数值。
2. **前提条件写成「状态」，不要写成「某事件已发生」**（除非确实是因果链）。这样历史偏离后，世界还能自洽运转。
3. **每条原本轨迹都要给玩家改变它的办法**，并在笔记里留下线索。
4. **选项必须都有代价**，不能有明显正确的选项。
5. **性格和行为一致**。忠诚 9 的人在原本轨迹里主动跳槽，必须写明强烈的原因。
6. **台词符合说话风格**。外籍选手的台词可以带少量母语或英语。
7. **负面事件**（假赛、暴雷、伤病）可以写，但要服务于玩法（警示、选择），不要只为制造惨剧。
8. **不写真实的人、战队、赛事和品牌。**

## 六、校验

### 1. 自动检查（`sim/test_cast.gd`，录入后必须通过）

- id 唯一；选手 ID 不重复；擅长英雄和专属能力都存在。
- 每支队正好 4 人，覆盖三个位置；全体女性约 1/3。
- 能力、潜力、名气在第二节的预算内。
- 关系两边都存在，且一致。
- 条件和效果只用第四节第 3 条的词汇；引用的角色、事件、flag 都存在。
- 原本轨迹不冲突：同一时间点同一队同一位置的首发只有一个人。
- 每条笔记绑定的轨迹事件存在。

### 2. 回放测试（`sim/season_cli.gd --replay N --years 5`，`--intervene 1` 为强干预）

让玩家战队「不干预」（自动训练、不转会、事件选默认项），连续模拟 S1–S5，跑 100 次：

| 检查 | 目标 |
|---|---|
| 原本轨迹的重现率 | 每条专属事件在不干预时发生的比例 ≥ 70%（概率小于 1 的事件按概率比较） |
| 世界年表的大事 | 各赛季的冠军和前世一致的比例 ≥ 40%（比赛有随机性，不要求完全一致） |
| 世界不崩 | 每支队始终 4 人；没有角色同时属于两支队；没有事件因为找不到人而报错 |

再跑一组「玩家强干预」（例如 S1 签下秦岚和 Rex），确认历史会明显偏离，笔记状态正确变成「已改变」或「不确定」。

## 七、审核清单

- [ ] 符合需求单（位置、性别、国籍、档次、故事功能）
- [ ] 一句话定位能让人记住，和已有角色不重复
- [ ] 能力、潜力、名气在预算内
- [ ] 原本轨迹的每条事件都有前提条件和概率，并和世界年表、其他角色不冲突
- [ ] 至少 1 条笔记能被玩家利用
- [ ] 至少 2 条关系，其中 1 条是冲突，并已合进关系总表
- [ ] 专属事件的选项都有代价，只用了标准词汇
- [ ] 结局 2–4 个，条件可判定
- [ ] 说话风格有 3 句以上示例台词
- [ ] 自动检查通过；核心角色加入后回放测试通过
