# NeonMOBA · 代码架构（阶段 0 之后）

原来 3300 行的 `main.gd` 已拆成以下模块。**对战逻辑（match）不依赖任何画面或界面**，可以无画面高速运行，同一个种子永远得到同一个结果。

```

game/

  rounds.gd             回合制 3V3 规则（阶段 1 核心模式）：购买阶段、占领核心、回合胜负、经济、地图节奏参数、读秒复活（次数、AI 是否复活）
  tuning.gd             全局手感倍率（弹速、英雄体积、移速），无依赖，hero.gd / kit_data.gd 直接 preload
  profiles.gd           选手数据：6 项能力、英雄熟练度和阶段、擅长英雄与专属能力
  runes_db.gd           英雄符文与选手专属能力的定义，以及「改动」格式

  consts.gd             共享常量（地图尺寸、图集行定义 ATLAS_ROWS / HERO_ROWS*）
  maps.gd               地图（地形、草丛、卡位点）；POOL = 联赛 BO3 的地图池

    cast_db.gd          固定世界的数据：16 支战队、核心角色、常规角色、职员、初始关系（docs/design/角色设计规范.md）
    world.gd            建立世界：build_fixed（固定世界，每局只有潜力和路人不同）、generate（随机的平行世界）；转会、退役、补员
    people.gd           角色状态与机制：上场面板（疲劳 / 状态 / 沟通 / 磨合 / 关系）、满意度、年龄曲线、退役、4 选 3

    events_db.gd        原本轨迹、选择事件、通用事件、前世笔记、结局
    story.gd            推进原本轨迹、通用事件、玩家的待处理消息、笔记状态、结局
    training.gd         周训练：能力经验、英雄熟练度、疲劳、AI 战队成长（阶段 3 C1/C2）
view/
  presenter.gd          表现层：特效、音效、镜头、震屏、世界绘制（地面、叠加层、小地图、英雄状态）
  grid.gd / ring.gd     背景网格、扩散光环
ui/
  hud.gd                局内界面：血条、技能栏、提示、击杀播报、计分板、结算画面
  shop_ui.gd            商店和背包界面（规则在 match.gd）
  menus.gd              主菜单、回合制 3V3 设置
  league_ui.gd          联赛界面：赛程、积分榜、战队、数据、新闻；系列赛选图禁选；亲自上场 / 观战 / 跳过

  player_input.gd       鼠标键盘操作和调试键

  test_items.gd         属性与装备单元检查
```

## 模块之间怎么通信

- 英雄、技能、AI 里的 `g` 指向 **`game/match.gd`**。
- **match → 表现层 / 界面**：
  - 特效和提示（`_ring`、`_burst`、`_popup`、`sfx`、`toast`、`_announce` 等）在 match.gd 末尾有**转发函数**。
  - 无画面运行时这些引用为 null，转发函数什么也不做。
  - 生命周期用信号通知：`world_cleared`、`match_started`、`match_ended(win)`，由 `main.gd` 连接到各界面模块。
- **界面 / 输入 → match**：通过 `gm.xxx` 直接读写。各模块之间用 `vw`（表现层）、`hd`（HUD）、`shp`（商店界面）、`mnu`（菜单）、`inp`（输入）互相引用，由 `main.gd` 注入。

## 固定步长与确定性（必须遵守的规则）

1. **时间**：match 只通过 `step(DT)` 前进，`DT = 1/60` 秒。`main.gd` 用累加器把渲染帧换算成固定步数。
2. **随机数**：
   - 玩法相关的随机数只能用 `g.rng`（match 的随机数生成器）。种子通过 `_start_rounds(..., match_seed)` 或 `reseed()` 设置。
   - 纯视觉的随机（粒子抖动、震屏、弹出字偏移）用表现层自己的 `vw.rng`，**不能**消耗 `g.rng`。否则开着画面和无画面运行的结果会不同。
3. **AI 的「性格随机」用 `_roll(key, 秒数)`**：在一个时间窗口内保持不变，不要每次思考都重新抽，否则思考越快行为越乱。
4. **不要用 `get_instance_id()` 做玩法判断**，它取决于内存分配。需要区分单位时用 `unit.uid`，它是每局从 0 开始编号的。阶段 0 就是因此修掉了站位随机的问题。
5. **模拟代码不能读界面状态**：比如弹出字数量、镜头位置、是否在屏幕内。这类判断放到表现层里（例如 `vw._popup` 自己决定显不显示）。
6. **调用新的表现函数**：在 match.gd 末尾加一个转发函数，不要直接引用 `vw`。

## 阶段 1：回合制、选手能力、符文

- **启动**：`match._start_rounds(a, b, diff, match_seed, setup)` 开始一局回合制。
  - `setup.profiles`：每队 3 名选手；
  - `setup.runes`：每队的符文页；
  - `setup.human = false`：全 AI，用于模拟。
- **选手能力如何影响 AI**：`hero_ai.gd` 里的 `apply_profile()` 把 6 项能力换算成 AI 参数，对照表写在该函数上方的注释里，比如反应对应思考间隔和躲技能概率。
  - 熟练度阶段乘在能力上；
  - 「生疏」只会用技能的主要用途，「熟悉」不会主动打连招；
  - 心态在压力局面（赛点、只剩一人）重新抽取一次能力波动。
- **躲技能**：技能脚本通过 `threats()` 上报地面预警和飞行中的弹道，AI 按反应能力决定是否躲开。纯数据英雄自动支持；手写技能脚本需要自己实现 `threats()`。
- **回合重置**：每回合开始调用技能脚本的 `round_reset()`，清掉残留的领域和弹道。手写技能脚本有残留物时要实现它。
- **符文和专属能力**：开局时由 `hero.apply_mods()` 应用。会先复制英雄的技能定义，不会改到 heroes_db 里共享的数据。
- **测量**：英雄身上的 `stats` 记录造成和承受的伤害、弹道命中、躲避尝试、被预警技能命中等数据，批量模拟器汇总输出。

## 地形与草丛

- `game/maps.gd`：地图定义，包括立柱（圆）、墙（矩形）、草丛（圆）、每队的卡位点。`setup.map` 选地图，默认 `core_pillars`；`core_open` 是无地形对照。
- `game/terrain.gd`：纯几何，无节点，结果确定。提供：
  - `push_out` 碰撞推出、`sweep` 位移撞墙；
  - `has_los` / `seg_blocked` 视线；
  - `path` 寻路（AStarGrid2D，40 像素格，路径拉直）；
  - `brush_at` 草丛查询；
  - `best_cover` 掩体选择。
- `match.gd`：
  - `clamp_pos` 限制在场地内并推出障碍，所有移动、位移、击退都经过它；
  - `has_los`、`blocked_at`（弹道技能撞墙停下）；
  - `visible_to(u, team)` 是草丛可见性，每步由 `_update_vis()` 计算；
  - `seen_foes` 和 `nearest_foe` 只返回看得见的对手。
- `hero.gd`：`_move_to` 经 `_steer_point` 自动寻路；攻击和施法会通过 `g.reveal()` 暴露自己 1.2 秒；指定目标技能需要视线。
- **规则**：AI 的感知必须用 `seen_foes` / `visible_to`，不要直接用 `foes_in`（那个用于伤害判定，不分可见与否）。
- 画面：`presenter._seen(h)` 按玩家队伍的视野决定是否画对手。

## 3C 操作（阶段 1.5）

- **虚拟手柄**：英雄每一步读取 `ctl_move`（移动方向）、`ctl_aim`（瞄准点）、`ctl_fire`（按住普攻）、`ctl_hold`（按住右键），技能用 `press(s)`。
  - 玩家输入（`input/player_input.gd` 的 `_hold_move`）每帧写入；
  - AI（`hero_ai.gd` 末尾的 driver `_drive`）每个模拟步写入；
  - 按 F6 托管时只有 AI 写。
- 旧的 `order_*` 指令系统已删除。
- **普攻**：
  - 远程：`match.spawn_bolt`，数据弹道 `match.bolts`，不追踪，被地形挡住，最远 1.5 倍攻击距离；
  - 近战：`match.foes_in_arc` 扇形判定。
  - 两种都走 `hero.attack_hit`（暴击、吸血、特效）。
  - AI 躲避通过 `match.bolt_threats` 并入 `threats_for`。
- **右键**：技能槽内部键仍是 `w`；`"c3": true` 的英雄开局自带、不升级。
  - 蓄力技能在技能上写 `"charge"`，蓄力值作为 `chg` 传给 `kit.cast(s, tgt, pos, chg)`；
  - `kit_data` 里任何数值都可以写成属性挂钩的字典（见 `docs/design/英雄设计体系_3C.md`）。
- **视野**：`hero.vision()`，全队共享。`match._compute_vis` 先看视野半径，再看草丛；AI 的 `seen_foes` / `nearest_foe` 自动遵守。
  - 玩家镜头高度由视野决定（`presenter._update_camera`），蓄力时可再拉高。
- 9 个英雄都已按 3C 重做；`kit_drift.gd` / `kit_blade.gd` 用 `kit_base.sval()` 读取属性挂钩的数值。

## 3C 实验（`exp3c/`）

- 独立场景 `exp3c/exp3c.tscn`，主菜单 [4] 用 `change_scene_to_file` 切过去，Esc 切回 `main.tscn`。
- 不依赖 match、hero 和 AI；`arena.gd` 管世界、镜头、子弹、界面，`sniper.gd` 是玩家角色，`dummy.gd` 是木桩。
- 不要求确定性，可以用全局随机数。冒烟测试：`godot --headless --fixed-fps 60 --script res://sim/smoke_3c.gd`，通过 `arena.test_input` 注入输入。

模拟的是回合制（旧的击倒竞赛已下线）。参数还有：`--attr_a`/`--attr_b`、`--set_a reaction=18`、`--prof_a 10`、`--runes_a r_vital=5`、`--sig_a anchor_wide_hook`、`--mirror`、`--map core_open`（默认 `core_pillars`；还有 `core_ring`、`core_gate`）。

- `--a` / `--b`：用逗号分隔的英雄 id，留空表示按职业随机补位。
- **输出**：
  - 每局一行 JSON：种子、阵容、胜方、比分、时长，以及每个英雄的等级、KDA、金钱和治疗量。
  - 最后一行汇总：胜负、平均时长、每分钟击倒数、耗时。
- **性能**：一局 5–8 分钟的 3V3 在无画面模式下约 2–4 秒。
- **验证结果**：10 个随机种子各跑两遍，结果完全一致。

## 已知限制

- 生存模式和旧 3V3 击倒竞赛已在阶段 1.5 下线并删除代码（怪物、刷怪、Boss、符文点、泉水）；旧版本在分支 `archive/v0-click-control`。训练模式到阶段 3 用 3C 操作重做。
- 英雄和怪物节点自带精灵图，所以无画面模式下仍会加载贴图。这些只是数据，不会影响结果。

## 存档与训练的约定（阶段 3）

- 训练状态都在赛季字典里：选手字典多了 `fatigue`（疲劳）和 `xp`（各能力经验），赛季字典多了 `train`（`ai_key` / `human_key` 记录已结算到哪一周，`plans` 玩家本周计划，`log` 上次结算报告）。老存档缺这些字段时 `Training.ensure()` 会补上。
- 训练的结算是**幂等**的：`Training.start_stage`（AI 战队，每周开始时）和 `Training.commit_human`（玩家战队，进入我方系列赛或「直接出结果」时）用周编号做标记，重复调用不会重复结算。常规赛周编号 = 周序号，季后赛 = 100 + 阶段序号。
- 疲劳惩罚只改比赛用的选手面板副本（`Training.in_form`），不改世界里的选手。
- 修改存档格式时：版本号 +1，在 `Save.migrate` 里补升级，并在 `test_save.gd` 里加旧版本样例。

## 固定世界与剧情（M1 / M2）

- **存档版本 2**：赛季字典里多了 `leagues`（两级联赛）、`no`（第几个赛季）、`history`、`moves`；世界里多了 `staff`、`rels`、`free`、`walkons`、`story`。版本 1 的存档不再读取（会直接开始新生涯）。
- **世界跨赛季延续**：`Season.next_season(season)` 返回新的赛季字典，`world` 是同一个对象（存档时随赛季一起保存）。剧情状态放在 `world["story"]`，所以跨赛季保留。
- **钩子**：`Season` 在这些时刻调用剧情引擎：`create` → `Story.start_career`；每个阶段开始 → `Story.on_stage_start`；每场系列赛结束 → `Story.on_series`；休赛期 → `Story.on_offseason`；新赛季 → `Story.on_new_season`；「直接出结果」玩家战队的比赛前 → `Story.auto_resolve`。
- **转会**：一律走 `World.move_player`（满员时放走「离开后阵容损失最小」的人，不会放走主角），之后 `World.fix_roster` 补到 4 人（优先签自由身，没有就生成路人；玩家战队只补路人）。
- **确定性**：剧情的随机数按「种子 + 赛季 + 周 + 阶段」生成；同一存档读回后继续推进，结果相同（`test_save.gd` 验证）。
- **加内容**：只改 `cast_db.gd` 和 `events_db.gd`，然后跑 `test_cast.gd` 和回放测试；不要在剧情内容里用词汇表以外的条件或效果。
