# NeonMOBA · 代码架构（阶段 0 之后）

原来 3300 行的 `main.gd` 已拆成以下模块。**对战逻辑（match）不依赖任何画面或界面**，可以无画面高速运行，同一个种子永远得到同一个结果。

```
main.gd                 组装各模块，驱动固定步长循环（约 100 行）
game/
  match.gd              一局比赛的模拟：单位、伤害、死亡复活、弹道、竞技场和生存规则、刷怪、商店规则
  consts.gd             共享常量（地图尺寸、图集行定义 ATLAS_ROWS / HERO_ROWS*、怪物表、生存事件表）
  enemy.gd / hero_shot.gd / enemy_shot.gd    怪物和弹道节点
view/
  presenter.gd          表现层：特效、音效、镜头、震屏、世界绘制（地面、叠加层、小地图、英雄状态）
  grid.gd / ring.gd     背景网格、扩散光环
ui/
  hud.gd                局内界面：血条、技能栏、提示、击杀播报、计分板、结算画面
  shop_ui.gd            商店和背包界面（规则在 match.gd）
  menus.gd              主菜单、生存选人、3V3 设置
input/
  player_input.gd       鼠标键盘操作和调试键
sim/
  sim_cli.gd            无画面批量模拟器
  smoke_ui.gd           界面冒烟测试
hero.gd / unit.gd / hero_ai.gd / team_ai.gd / kit_*.gd / heroes_db.gd / items_db.gd   没有变化（只把 g 指向 match）
```

## 模块之间怎么通信

- 英雄、技能、AI 里的 `g` 指向 **`game/match.gd`**。
- **match → 表现层 / 界面**：
  - 特效和提示（`_ring`、`_burst`、`_popup`、`sfx`、`toast`、`_announce` 等）在 match.gd 末尾有**转发函数**。
  - 无画面运行时这些引用为 null，转发函数什么也不做。
  - 生命周期用信号通知：`world_cleared`、`match_started`、`match_ended(win)`，由 `main.gd` 连接到各界面模块。
- **界面 / 输入 → match**：通过 `gm.xxx` 直接读写。各模块之间用 `vw`（表现层）、`hd`（HUD）、`shp`（商店界面）、`mnu`（菜单）、`inp`（输入）互相引用，由 `main.gd` 注入。

## 固定步长与确定性（必须遵守的规则）

1. **时间**：match 只通过 `step(DT)` 前进，`DT = 1/60` 秒。`main.gd` 用累加器把渲染帧换算成固定步数。
2. **随机数**：
   - 玩法相关的随机数只能用 `g.rng`（match 的随机数生成器）。种子通过 `_start_arena(..., match_seed)` / `_start_survival(..., match_seed)` 或 `reseed()` 设置。
   - 纯视觉的随机（粒子抖动、震屏、弹出字偏移）用表现层自己的 `vw.rng`，**不能**消耗 `g.rng`。否则开着画面和无画面运行的结果会不同。
3. **不要用 `get_instance_id()` 做玩法判断**，它取决于内存分配。需要区分单位时用 `unit.uid`，它是每局从 0 开始编号的。阶段 0 就是因此修掉了站位随机的问题。
4. **模拟代码不能读界面状态**：比如弹出字数量、镜头位置、是否在屏幕内。这类判断放到表现层里（例如 `vw._popup` 自己决定显不显示）。
5. **调用新的表现函数**：在 match.gd 末尾加一个转发函数，不要直接引用 `vw`。

## 无画面批量模拟

```
godot --headless --script res://sim/sim_cli.gd -- --games 30 --seed 1 --a frost,ember,tide --b ",," --diff 1 --out /tmp/r.jsonl
godot --headless --script res://sim/sim_cli.gd -- --games 5 --check     # 每个种子跑两遍，检查结果是否一致
godot --headless --fixed-fps 60 --script res://sim/smoke_ui.gd            # 界面冒烟测试，输出里不应有 SCRIPT ERROR
```

- `--a` / `--b`：用逗号分隔的英雄 id，留空表示按职业随机补位。
- **输出**：
  - 每局一行 JSON：种子、阵容、胜方、比分、时长，以及每个英雄的等级、KDA、金钱和治疗量。
  - 最后一行汇总：胜负、平均时长、每分钟击倒数、耗时。
- **性能**：一局 5–8 分钟的 3V3 在无画面模式下约 2–4 秒。
- **验证结果**：10 个随机种子各跑两遍，结果完全一致。

## 已知限制

- 生存模式也在 match 里，可以无画面运行，但 `sim_cli.gd` 目前只模拟 3V3。
- 英雄和怪物节点自带精灵图，所以无画面模式下仍会加载贴图。这些只是数据，不会影响结果。
