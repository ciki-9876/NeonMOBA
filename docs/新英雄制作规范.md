# NeonMOBA · 新英雄制作规范

适用对象：参与 NeonMOBA（Godot 4.7 / GDScript，仓库 `ciki-9876/NeonMOBA`）开发的 Agent。
目标：**新增一个英雄 = 1 个数据条目 + 美术 + 极少量接线，不改 AI 代码。** 只有机制特殊（召唤物、变身、持续引导）时才写专用脚本。

## 0. 先读什么

| 文件 | 作用 |
|---|---|
| `heroes_db.gd` | 所有英雄数据。6 个现有英雄是最好的模板：`aegis/anchor/lumen/seer`（纯数据）、`drift/blade`（手写 kit） |
| `kit_data.gd` | 效果积木解释器；同时负责 AI 元数据推断和技能说明自动生成 |
| `kit_base.gd` | 手写 kit 的钩子（`cast/on_attack_fire/on_attack_hit/tick/est_damage/ai_meta/...`） |
| `hero_ai.gd` / `team_ai.gd` | 通用英雄 AI / 3V3 团队大脑。**一般不要改**，见第 6 节 |
| `unit.gd` | 通用状态：buff（root/taunt/banish/dr/haste/as/armor/regen）、护盾、驱散 |
| `items_db.gd` | 物品。由 `tools/gen_items.py` 生成，**不要手改**；`build` 里只引用其 `ORDER` 中的 id |

## 1. 设计规范

**1. 先定职业**（`role`）：`tank` 坦克 / `carry` 输出 / `support` 辅助。队伍 AI 会按职业站位（坦克在前、输出居中、辅助在后），随机选人也按职业补位。一个英雄的技能组要能支撑它的职业：
- 坦克：至少 1 个先手/控制 + 1 个保护或减伤；自带被动坦度（`dr/regen/armor`）。
- 输出：至少 1 个主要伤害技能 + 1 个位移或控制用于接近/脱身；终极技能要有收割或爆发作用。
- 辅助：至少 1 个对友方的治疗/护盾/救人技能 + 1 个对敌方的控制或伤害。

**2. 技能槽固定 Q W E R**：E 通常是被动，R 是终极（`max: 3`，6/12/18 级可学）。Q/W/E `max: 4`。

**3. 数值参考**（现有 6 个英雄的量级，新英雄应落在同一范围，避免一个英雄压倒全场）：
- 单体伤害 Q：90–300（随等级），冷却 4–16s，耗蓝 60–110。
- 坦克技能耗蓝要低（Q/W 60–90，R 120–200），否则 AI 蓝不够放不出大招（已踩过）。
- 治疗/护盾偏保守：单体治疗 90–240，全队治疗 180–420，护盾 90–280。治疗过强会让 3V3 十几分钟打不死人。
- 控制时长：单体 0.6–2.2s，群体晕眩 1.4–2.2s；大招冷却 50–100s。
- 基础属性：`base` 力/敏/智总和约 55–60，`gain` 总和约 6.5–7.5；坦克 `armor` 2–4、近战 `range` 150；远程 `range` 520–550、`proj_speed` 1000–1100。

**4. 必须写清楚的文案**：`name`（≤6 个汉字）、`title`（"职业 · 主属性 · 风格"）、`blurb`（一句话）、`combo`（连招/配合思路，AI 不读，玩家看）。
**5. 字体**：游戏字体缺少部分汉字（已确认 敌/杀/远 显示为方块）。文案避开这些字，用 对手/击倒/射手。新字请在游戏里确认能显示。

## 2. 数据条目（`heroes_db.gd`）

在 `HEROES` 里加条目，并把 id 加进 `ORDER`（顺序决定选人界面顺序）。必填字段（以 `aegis` 为模板复制）：

```
"id": {
  "name","short","role","title","blurb",
  "primary": "str|agi|int", "base": {str,agi,int}, "gain": {str,agi,int},
  "base_dmg","bat","range","ms","armor","melee",
  "atk_point","backswing","proj_speed","turn","radius",   # 前摇/后摇秒数；近战 proj_speed=0
  "sprite": "<id>", "kit": "res://kit_data.gd", "col": Color(...),   # col 数值可 >1（发光）
  "icons": {"q":"<id>_q","w":"<id>_w","e":"<id>_e","r":"<id>_r"},
  "skills": { "q":{...}, "w":{...}, "e":{...}, "r":{...} },
  "combo": "...", "ai_learn": ["q","w","e"], "build": [物品id...]
}
```

- 技能里**任意数值都可以写成按等级的数组**（取 `[等级-1]`，越界取末项），例如 `"cd": [14,13,12,11]`。
- 技能通用字段：`name, type, max, ind, mana, cd, cast_point, range, radius, width`。
  - `type`：`passive | no_target | point | unit | ally | unit_or_point`（`ally` = 以友方为目标）。
  - `ind`（施法指示）：`line | blink | circle | dash | unit | ally | self`。
- **`ai_learn`**：AI 的加点优先顺序，R 到 6/12/18 级自动学，不用写。
- **`build`**：AI 出装顺序，从 `items_db.gd` 的 `ORDER` 里选 id，6–9 件。坦克出 `phase/vitality/perseverance/ac/heart` 一类，辅助出 `sage/aether/octarine` 一类，输出出攻击和暴击类。
- 没有 `tips` 字段时，技能说明由 `kit_data.gd` 从效果自动生成；只有手写 kit 才需要手写 `tips`。

### 2.1 技能效果积木（纯数据英雄的核心）

技能 = `"effects": [ {...}, {...} ]`，每块 `{"do": 操作, "on": 选择器, ...参数}`。

- **选择器 `on`**：`target`（技能目标）/ `self` / `enemies`（范围内对手）/ `allies`（范围内友方）/ `all_allies` / `line`；范围类配 `"at": "pos|self|target"` 和 `"r": 半径`。
- **操作 `do`**：
  - 伤害与治疗：`damage {amt, amt_hp, dtype: magic|phys|pure}`、`heal {amt, pct}`、`barrier {amt, amt_hp, dur}`
  - 控制：`stun/root/silence/taunt/banish {dur}`、`slow {pct, dur}`、`cleanse {strong}`
  - 增益：`buff {id: haste|as|armor|dr|regen, v, dur}`、`status {id: mark|charged, dur}`
  - 位移：`dash {to: target|pos, speed, max, then:[...]}`、`pull {to: caster|pos, speed}`
  - 弹道/延迟/领域：`shot {speed,len,w,pierce,then:[...]}`、`delay {t,r,then:[...]}`、`zone {dur,tick,r,each:[...]}`
  - 表现：`fx {kind: ring|burst, at, r, col}`、`sfx {name, pitch, vol}`、`shake {v}`
- 被动：`"type": "passive", "passive": {dr, regen, armor, as, ms, aura: {id, v, r}}`。
- 可用音效名：attack ahit lance blink nova chain singularity collapse learn deny slam whistle silence mend fuse rune boss（以及 shoot hit explode boom pickup levelup hurt dash select zap warning）。需要新音效：加到 `tools/gen_audio2.py` 重新生成 wav，并加入 `main.gd` 的 `_load_assets` 音效列表。
- **缺积木怎么办**：优先在 `kit_data.gd` 的 `_do()` 里**新增一个通用积木**（并在 `_walk()` 里补上它对应的 AI 角色、在 `_desc()` 里补说明），这样以后所有英雄都能用；不要为单个英雄写特例。

### 2.2 `ai` 覆盖（可选，仅在推断不准时）

AI 会从效果自动推断技能角色（nuke / disable / soft / gap_close / escape / aoe / heal / save / buff_ally / buff_self / ult / team_heal）、瞄准方式、半径、预估伤害和治疗。只有推断不准时，才在技能里加 `"ai": {...}` 覆盖：

| 键 | 含义 |
|---|---|
| `roles` | 直接指定角色列表 |
| `aim` | `target / unit / ally / cluster / self` |
| `radius` / `min_heroes` / `min_creeps` | 范围技能值得放的最少人数（大招建议 `min_heroes: 2`） |
| `prefer_status` / `setup_status` | 连招提示：需要目标带某状态才更好 / 本技能为谁上状态 |
| `save_hp` | 友方血量低于该比例才对其放救人技能（如 0.3） |
| `ult` | 手动标记为大招（`r` 默认就是） |
| `est_dmg` / `est_heal` | 预估伤害/治疗，推断不准时覆盖 |

## 3. 美术

- **角色**：18×18 像素、2 帧（待机），放大 3 倍显示；**技能图标**：32×32，每英雄 4 个。命名 `<id>`、`<id>_q/w/e/r`。
- 生成方式二选一：Aseprite Lua（`tools/neondrift_heroes2.lua`），或 Python/PIL（`tools/gen_heroes3.py`，无需 Aseprite，`python3 tools/gen_heroes3.py art/heroes3.png`，同一套绘制函数）。参考 `tools/neondrift_heroes2.lua`（铁壁/重锚/圣光/星语）和 `tools/neondrift_heroes.lua`（绯刃）。脚本把各行自上而下、1px 间隔打包成**宽 64px 的图集** `art/heroesN.png`。
- **图集行顺序必须与 `main.gd` 里对应的 `HERO_ROWS*` 常量完全一致**（`[名字, 宽, 高, 帧数]`）。新英雄做法：新建 `art/heroes3.png` + `HERO_ROWS3`，并在 `_load_assets()` 里加一行 `_slice("res://art/heroes3.png", HERO_ROWS3)`；不要往已有图集中间插行。
- 风格：深色描边 `0b0d1a`、霓虹发光主色，与英雄 `col` 一致；职业剪影要可辨（坦克宽厚、辅助带光环/法杖、输出带武器）。
- 新 PNG 需要被 Godot 导入（打开编辑器会生成 `.import`）；提交时一起提交 `.import`。

## 4. 接线检查清单（改动点汇总）

1. `heroes_db.gd`：新条目 + `ORDER`。
2. `art/`：图集 PNG + `main.gd` 里的 `HERO_ROWS*` 与 `_slice` 调用。
3. `main.gd`：选人界面是按 `HeroesDB.ORDER` 生成的网格卡片（3 列，外面包了 ScrollContainer，鼠标滚轮翻页；已在 9 个英雄时验证）；3V3 设置里的 OptionButton 也读 `ORDER`，下拉列表随英雄数自动变长。超过约 15 个英雄时再考虑按职业分页。`ORDER` 里按"坦克 / 输出 / 辅助"各一排排列，这样每行就是一个职业。
4. 手写 kit 才需要：`kit_<id>.gd`（继承 `kit_base.gd`）+ 条目里 `"kit": "res://kit_<id>.gd"`。
5. 不需要改：`hero.gd`、`hero_ai.gd`、`team_ai.gd`、`unit.gd`（除非加新通用状态，见第 6 节）。

> `main.gd` 是单文件（约 3300 行）。多人并行改动时，把改动限制在上面几处，避免冲突。

## 5. 手写 kit（仅特殊机制）

继承 `kit_base.gd`，只重写需要的钩子。**必须实现 AI 所需的信息**，否则 AI 不会用这个技能：
- `est_damage(s)`、`est_heal(s)`：AI 做击杀/治疗决策。
- `ai_meta(s)`：返回 `{roles, aim, radius, ...}`；可以直接在条目里写 `"ai"` 块，默认实现会读取它。
- `busy()`：kit 接管英雄时返回 true（例如连斩期间）。
- `tip(s)`：手写 `tips` 文案。
- `draw(o)`：世界空间的预警/领域绘制。
参考 `kit_drift.gd`（标记→引爆）和 `kit_blade.gd`（冲刺烙印 + 连斩）。

## 6. AI：什么时候需要动

**默认不动。** 通用 AI（`hero_ai.gd`）按技能角色决策：打击/控制接力（不对已被控的人叠控制，被控后补伤害）、突进、逃生、AoE 聚集、治疗/救人评分、撤退阈值（输出 0.18、坦克 0.15 血线）、按职业站位、出装、加点；`team_ai.gd` 负责集结/开团/撤退意图、集火目标、保护请求、前排先进场。

**需要给 AI 加能力的情形**（做法：先在通用层加，不要为英雄写分支）：
- 新增通用状态（如"沉默友方""复活"）→ `unit.gd` 增加 buff id，`kit_data.gd` 增加积木，`_walk()` 里给出 AI 角色，`hero_ai.gd` 的相应评分里使用该角色。
- 新 AI 角色 → 在 `hero_ai.gd` 的 `_try_skills`/`_try_support` 加评分分支，**保证现有英雄行为不变**，并在本文第 2.2 节登记。
- 团队层面（如"保护后排辅助"）→ `team_ai.gd`。

## 7. 验证（必须做，且要如实报告）

沙盒里无法运行 Godot，所以分两层：

1. **静态检查**（在任何环境）：`pip install gdtoolkit==4.*`，对每个改动过的 `.gd` 跑 `gdparse file.gd`，必须无报错。
2. **在 Godot 4.7 编辑器里实跑**：
   - 菜单进入 3V3，把新英雄放进一队，其余随机；按 **F6 自动驾驶** 让玩家也由 AI 操控，看至少 1–2 局到出结果。
   - 调试键（调试构建）：F6 自动驾驶、F7 +3000 金币、F9 升级/加时、F10 无敌、F8 召 Boss（生存模式）。
   - 逐个技能手动放一遍：Q W E R 是否有效果、说明是否准确、指示器是否正确、耗蓝是否放得出来。
   - 看 AI：技能是否真被使用（控制/治疗/救人/大招）、站位是否符合职业、不会站着不动或卡墙。
   - 在输出里**逐项说明测过什么、没测什么**。
3. **常见编译坑**（均出现过）：`:=` 不能从 Variant 推断类型，要显式写 `var x: float = ...`；不要用与基类同名的变量（`kind` 在 `hero.gd`、局部变量 `setup`）；`kit_data` 里字典取值要 `float()/int()`；部署时只部署成对的 `unit.gd`/`hero.gd`，否则会报 `Identifier not found`。
4. **平衡经验（新增）**：新英雄加入后实测 3V3 每分钟击倒数从基线 2.3–2.9 升到 3.6–6.5。主要推手是"减速 + 定身 + 范围伤害"的叠加。处理顺序：先降单次伤害（约 -18%）和定身时长（≤1.4s），再看耗蓝。**耗蓝是节奏杠杆**：把坦克和辅助耗蓝降得过低，大招放得更勤，击倒数会飙到 6/分钟以上；调回中间值（坦克大招 130–170）后回到 3.1–3.7。每次调整后至少再跑 2 局确认，单局方差很大（3.1–4.3）。
5. **平衡（原则）**：用 AI 对 AI 跑多局（≥6 局）看击倒速度。参照：3V3 先到 15 次击倒，**目标每分钟约 2–3 次击倒**；一局 12 分钟还没分出胜负说明坦度/治疗过高，30 秒结束说明爆发过高。再看新英雄的胜率/伤害/治疗量是否离群。

## 8. 提交规范

- 一个英雄一次提交：`heroes_db.gd`（+ kit）、`art/*.png(+.import)`、`tools/*.lua`、`main.gd` 的少量接线。
- 提交说明写：英雄名、职业、技能一句话、**已验证/未验证项**。
- 不要提交 `.godot/`（已在 `.gitignore`）。不要手改 `items_db.gd`。
- 做完把英雄设计（技能表、数值意图、连招）更新到项目文档 `claude/英雄与AI框架.md`。
