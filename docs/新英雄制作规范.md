# NeonMOBA · 新英雄制作规范（3C 版）

适用对象：参与 NeonMOBA（Godot 4.7 / GDScript，仓库 `ciki-9876/NeonMOBA`）开发的 Agent。
设计规则的准绳是 `docs/design/英雄设计体系_3C.md`，先读它。
目标：**新增或重做一个英雄 = 1 个数据条目 + 美术 + 极少量接线，不改 AI 代码。** 只有机制特殊（召唤物、变身、持续引导）时才写专用脚本。

## 0. 先读什么

| 文件 | 作用 |
|---|---|
| `docs/design/英雄设计体系_3C.md` | 操作、属性（攻击距离、弹道速度、视野）、普攻、右键规则 |
| `heroes_db.gd` | 英雄数据，共 12 个。模板：`frost`（近战坦克）、`ember`（远程输出，蓄力右键）、`tide`（远程辅助，友方右键）、`aegis`（冲向鼠标的位移右键）；手写技能：`drift`（蓄力光束）、`blade`（冲刺 + 标记） |
| `kit_data.gd` | 效果积木解释器；同时负责属性挂钩数值、蓄力、AI 元数据推断、技能说明自动生成 |
| `kit_base.gd` | 手写 kit 的钩子 |
| `hero.gd` | 虚拟手柄（`ctl_move/ctl_aim/ctl_fire/ctl_hold`、`press()`）、普攻（远程弹道、近战扇形）、属性 |
| `hero_ai.gd` / `team_ai.gd` | AI。决策层选目标和技能，末尾的「3C driver」把意图变成手柄输入。**一般不要改**，见第 6 节 |
| `items_db.gd` | 物品，由 `tools/gen_items.py` 生成，**不要手改** |

## 1. 设计规范

**1. 先定职业**（`role`：`tank` / `carry` / `support`）和远近战（`melee`）。
- 坦克：至少 1 个先手或控制 + 1 个保护或减伤；自带被动坦度。
- 输出：至少 1 个主要伤害技能 + 1 个位移或控制；大招有收割或爆发作用。
- 辅助：至少 1 个对友方的治疗、护盾或救人技能 + 1 个对敌方的控制或伤害。

**2. 技能槽：右键、Q、E、R**（内部键 `w` `q` `e` `r`）。
- **右键（`w`）**：
  - 一定是主动技能，`"max": 1`，不升级，开局就有；
  - 伤害和治疗写成属性挂钩（第 2.1 节），这样才能随装备成长；
  - 优先放英雄的**特色技能**；可以做成蓄力技能。
- Q / E：可升级 4 级，可以是被动。
- R：大招，`"max": 3`，6/12/18 级可学，可以是被动。

**3. 瞄准方式**：
- 对敌技能做成方向技能（`point` + `shot` 或 `line`）或地点技能（`point` + 范围），朝鼠标释放。
- 不再做「点选敌方单位」的技能。
- 对友方技能用 `ally`：自动锁定离鼠标最近的友方，没有就作用于自己。

**4. 数值参考**（3C 英雄的量级）：
- **普攻**：
  - 远程：`range` 440–480（弹道最远 1.5 倍），`proj_speed` 1000–1200；
  - 近战：`range` 150，`arc` 90–130°。近战普攻是范围伤害，基础攻击力略低于远程。
- **视野** `vision`：坦克约 850，输出约 950，辅助约 1000。决定玩家镜头高度和 AI 感知范围。
- **英雄面板** `stats`（固定值，升级不加属性，属性只来自装备、符文和被动）：
  - 生命：坦克 1500–1650，近战输出约 1450，远程输出 1100–1300，辅助 1000–1100（回合制里再 ×0.8）；
  - 攻击力 80–96；攻击间隔：远程 0.95–1.27 秒，坦克 1.24–1.36 秒；
  - 物防 37–56，法防 37–43；法力：坦克约 450–500，输出 480–800，辅助 720–760；
  - 生命回复：坦克约 7，其他 4.7–6.7；法力回复 2.1–3.5；移速 295–315。
- **右键**：
  - 物理输出：约 30 + 0.7×攻击力（12 级裸装约 90）；
  - 坦克：约 30 + 5–7.5% 最大生命；
  - 法师和辅助：固定值，伤害约 95–170、治疗约 125–130（由技能强度放大）；
  - 冷却 4–13 秒，耗蓝 50–80。
- **英雄强化**：写 `shard_note` + `shard`（特化芯片强化右键）和 `scepter_note` + `scepter`（终极协议强化 R），修改列表格式与符文相同（`game/runes_db.gd` 顶部注释），强度约等于「再升一级」。
- **QER**：
  - 单体伤害 90–300（随等级），冷却 4–16 秒，耗蓝 60–130；
  - 坦克耗蓝要低（Q 45–90，R 120–200），否则 AI 放不出大招；
  - 控制：单体 0.6–2.2 秒，大招冷却 50–100 秒。
- 回合制里英雄血量 ×0.55（`rounds.gd` 的 `HP_MULT`），一次满伤害的技能组能打掉脆皮大半到全部。
- 弹速、半径、移速在运行时还会乘 `game/tuning.gd` 的全局倍率（弹速 ×1.35 / ×1.3、体积 ×1.3、移速 ×0.88），数据里按原来的范围填。
- 平衡参照：`docs/design/英雄设计体系_3C.md` 第七节的 12 英雄胜率表；新英雄在随机阵容下胜率应落在约 35–65%。
- **AI 对 AI 时范围伤害和控制最值钱**：只有单体伤害的英雄（例如第一版鹰隼）胜率会极低。每个英雄至少要有一个范围或控制技能，输出英雄最好每个技能都带一点控制或减速。
- 加入英雄后，更新联赛用的英雄强度先验 `game/league/draft.gd` 的 `HERO_PRIOR`（(胜率 − 50%) ÷ 100），否则 AI 禁选和「直接出结果」会把新英雄当作平均强度。

**5. 文案**：
- `name`（不超过 6 个汉字）、`title`（「职业 · 近战/远程 · 风格」）、`blurb`、`combo`；
- 说明里提到按键时写「右键」，不要写「W」。

## 2. 数据条目（`heroes_db.gd`）

以 `ember`（远程）或 `frost`（近战）为模板复制，加入 `ORDER`：

```
"id": {
  "name","short","role","title","blurb", "c3": true,
  "stats": {"hp", "atk", "interval", "def", "res", "mana", "hpr", "mpr", "ms"},   # 固定面板（见第 1 节第 4 条）
  "range","melee",
  "arc": 110.0,                     # 近战扇形角度（度）；远程可省略
  "atk_point","backswing",          # 前摇 / 后摇秒数，随攻速缩短，期间可以移动
  "proj_speed",                     # 远程普攻弹道速度；近战 0
  "vision",                         # 视野
  "radius", "sprite", "kit": "res://kit_data.gd", "col": Color(...),
  "icons": {"w": 右键图标, "q", "e", "r"},
  "skills": { "w": {...右键...}, "q": {...}, "e": {...}, "r": {...} },
  "shard_note", "shard": [修改...], "scepter_note", "scepter": [修改...],
  "combo": "...", "ai_learn": ["q", "e"], "build": [目标装备 id...]   # AI 会按配件逐步合成；可含 chipx / protocol
}
```

- `"c3": true` 标记这是 3C 英雄：开局自带右键，右键不占技能点。
- `turn`（转身速度）已不使用，可以省略。
- 技能通用字段：`name, type, max, ind, mana, cd, cast_point, range, radius, width`。
  - `type`：`passive | no_target | point | ally`（`unit` 只为旧英雄保留）；
  - `cast_point` 建议 0.15–0.3，施法期间站定。

### 2.1 技能效果积木

技能 = `"effects": [ {...}, ... ]`，每块是 `{"do": 操作, "on": 选择器, ...参数}`。

- **选择器 `on`**：`target`（弹道命中的单位或友方目标）、`self`、`enemies`、`allies`、`all_allies`、`line`。范围类配 `"at": "pos|self|target"` 和 `"r"`。
- **操作 `do`**：
  - 伤害与治疗：`damage {amt, amt_hp, dtype}`、`heal {amt, pct}`、`barrier {amt, amt_hp, dur}`
  - 控制：`stun/root/silence/taunt/banish {dur}`、`slow {pct, dur}`、`cleanse`
  - 增益：`buff {id, v, dur}`、`status {id, dur}`
  - 位移：`dash {to: pos, speed, max, then}`、`pull`
  - 弹道、延迟、领域：`shot {speed, len, w, pierce, then}`、`delay {t, r, then}`、`zone {dur, tick, r, each}`
  - 表现：`fx`、`sfx`、`shake`
- **属性挂钩的数值**：任何数值参数都可以写成
  `{"v": 基础值或按等级数组, "atk": 系数, "hp": 系数, "charge": [无蓄力倍率, 满蓄力倍率]}`。
  例：`"dmg": {"v": 30, "atk": 0.72}`。说明会自动显示公式和当前数值。技能强度对所有技能统一生效，不用写进数据。
- 被动 `passive` 的键：`dr, regen, def, as, ms, aura`；增益 `buff` 的 `id`：`haste, as, def, res, dr, regen`（物防按「防御 ÷（防御 + 100）」减伤，约 6 点 = 旧护甲 1 点）。
- 旧格式（三围）英雄可以用 `tools/convert_heroes_stats.py heroes_db.gd` 一键转换。
- **蓄力**：技能上加 `"charge": {"time": 1.0, "min": 0.15, "move": 0.55, "zoom": 0.85}`。
  - 按住右键蓄力，松开释放；
  - 参数里的 `"charge": [a, b]` 倍率随蓄力从 a 变到 b；
  - AI 会自动按住到想要的蓄力程度再放（操作越好蓄得越满）。
- 缺积木时，在 `kit_data.gd` 的 `_do()` 里**新增通用积木**，同时补 `_walk()`（AI 角色）和 `_desc()`（说明）。

### 2.2 `ai` 覆盖（可选）

AI 从效果自动推断技能角色、瞄准方式、半径、预估伤害和治疗（蓄力技能按满蓄力估算）。只有推断不准时才加 `"ai": {...}`：`roles`、`aim`、`radius`、`min_heroes`（大招建议 2）、`prefer_status` / `setup_status`、`save_hp`、`est_dmg` / `est_heal`。

## 3. 美术

- 角色 18×18 两帧，技能图标 32×32 每英雄 4 个。重做的英雄可以沿用原图标，用 `icons` 重新对应到右键 / Q / E / R。
- 新图集：`tools/gen_heroes3.py`（Python/PIL）或 Aseprite Lua。行顺序必须与 `game/consts.gd` 的 `HERO_ROWS*` 一致，在 `game/match.gd` 的 `_load_assets()` 里加 `_slice`；提交 `.import`。

## 4. 接线检查清单

1. `heroes_db.gd`：新条目，加入 `ORDER`（按坦克 / 输出 / 辅助每行一个职业排列）。
2. 美术：图集 + `HERO_ROWS*` + `_load_assets()`。
3. 不需要改：`hero.gd`、`hero_ai.gd`、`team_ai.gd`、`unit.gd`、界面（选人、技能栏、提示都读数据）。
4. **确定性**：玩法随机只用 `g.rng`；不要用 `get_instance_id()`，用 `unit.uid`。

## 5. 手写 kit（仅特殊机制）

继承 `kit_base.gd`：
- `cast(s, tgt, pos, chg)`：`chg` 是蓄力 0–1；
- AI 需要 `est_damage`、`est_heal`、`ai_meta`；
- 其他可选：`busy`、`tip`、`draw`、`threats`、`round_reset`。

参考 `kit_drift.gd`（蓄力光束，用 `sval("w", "dmg", chg)` 读属性挂钩数值）和 `kit_blade.gd`（冲刺、标记、`check()` 校验大招目标）。

## 6. AI：什么时候需要动

**默认不动。** 3C 下 AI 分两层：
- **决策层**：选目标、撤退、救人、技能评分、团队意图。
- **执行层**（`hero_ai.gd` 末尾的 driver）：
  - 预判瞄准（提前量 = 距离 ÷ 弹速 × 目标速度），每发误差由「操作」决定；
  - 瞄准跟手速度由「反应」决定；
  - 远程保持约 85% 攻击距离并侧移走位，近战贴近；
  - 躲普攻弹道和技能（反应）；
  - 蓄力技能按住到目标蓄力再放。

需要新能力时，在通用层加，保证现有英雄行为不变。

## 7. 验证（必须做，且要如实报告）

1. `gdparse` 每个改动的 `.gd`。
2. **无画面**（Godot 4.7 Linux 版可装在沙盒里）：
   - `godot --headless --script res://sim/sim_cli.gd -- --games 10 --check`：结果可复现，没有 SCRIPT ERROR。
   - `godot --headless --fixed-fps 60 --script res://sim/smoke_rounds.gd`：输出里没有 SCRIPT ERROR；
   - `godot --headless --script res://sim/test_items.gd`：属性和装备的单元检查全部 PASS。
   - 平衡：`--games 10 --a <新英雄>,, --out r.jsonl` 多跑几批，看新英雄的普攻命中率、伤害、承伤是否离群；回合结束方式大致为占领 60–75%、团灭 25–40%。
3. **在编辑器里实跑**：
   - 回合制 3V3，用新英雄亲自打：WASD、左键、右键（蓄力）、QER 逐个试；
   - 再按 F6 让 AI 托管看一局；
   - 调试键：F6 托管、F7 +3000 金币、F10 无敌。
4. 常见编译坑：`:=` 不能从 Variant 推断类型；不要用与基类同名的变量；字典取值要 `float()` / `int()`。
