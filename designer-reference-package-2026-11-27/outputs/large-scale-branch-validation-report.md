# 大规模剧情分支工程验证记录

## 结论

在当前 **50 名选手、10 支战队、5 个赛季** 的实验规模下，人物目标、关系、阵容竞争、转会、士气和导师关系可以由一组可检查的规则共同演化。不同选择能够形成不同的后续世界；事件记录可核对人物、动机、触发前提、结果，以及已建立的前因引用。

这验证了原型层面的工程可行性：剧情走向可以由人物状态和规则组合生成，不需要为每个人预先手写并保存所有分支。它还没有验证自然语言剧情质量，也没有穷尽所有可能的故事结局。

## 实验设置

- 每条路线有 5 个赛季；每季自动生成一次决定，包含签约、训练、双排、观察和三人连锁场景。
- 使用固定随机种子生成 1,000 条路线，保证实验可以复跑。
- 对其中 64 条相同决定序列进行复跑，核对结果是否完全一致。
- 对其中 128 条路线把一个决定替换成“观察”，比较最终人物和关系状态。
- 另外准备 9 个固定场景：搭档、队内摩擦和导师关系各有正反条件；三人连锁覆盖首发竞争与主动转会；全队首发满员场景覆盖转会受阻；极限训练验证个人成长上限。

## 观察结果

| 检查项 | 结果 |
|---|---:|
| 五赛季路线 | 1,000 条 |
| 不同的人物与关系结局状态 | 998 种 |
| 选手、阵容、关系与成长上限违规 | 0 条路线 |
| 剧情字段或因果引用问题 | 0 条路线 |
| 相同决定序列复跑一致 | 64 / 64 |
| 替换一个决定后结局发生变化 | 85 / 128 |
| 剧情记录 | 11,896 条 |
| 明确连接到前因事件的剧情记录 | 2,438 条 |
| 最长连续因果链 | 3 段事件 |
| 六种剧情规则覆盖 | 6 / 6 |
| 固定触发和边界场景 | 9 / 9 通过 |

随机路线中没有自然触发“转会受阻”，因此专门构造了“其他战队首发全部满员”的边界场景验证这条规则。其余规则在随机路线或固定场景中都有覆盖。

## 找到并修复的问题

第一轮 1,000 条路线发现 24 条训练选择让选手的操作值超过个人成长上限。修正后，同一批固定种子路线重新运行，违规数量降为 0。这个缺陷说明批量规则检验能找到单次手动操作不容易覆盖的组合问题。

## 结果的适用范围

998 种结果指可观察的选手、关系、阵容、士气和导师状态组合，不等于 998 个经过编剧润色的故事文本。测试验证的是规则能否组合、状态能否保持一致、选择是否造成后续差异，以及这些差异是否可追踪。

本轮没有穷举所有决定序列。它验证了固定规则下的一千组样本，以及少量明确设计的边界条件。当前规模也只有 50 名选手和 5 个赛季，不能据此断言更大阵容或更长年表的运行成本。

## 如何复核

打开 [实验页面](world-model-engineering-bench.html)，按界面推进到“核对赛果”，点击“自动跑 1000 条发展路线”。测试会逐批显示进度，并列出人物发展规则、触发次数和边界场景结果。

结论：**在这个原型规模上，动态剧情分支的状态模拟、规则组合、重复复现和因果核对均已跑通；下一轮应扩展到更多人物与更长时间，再单独评估故事文本是否连贯、是否值得玩家关注。**
